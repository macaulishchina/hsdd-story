# HSDD Story 设计说明

版本：v1。本文件描述产品行为，启动和测试方法见 [README](../README.md)。

## 目标

人不翻聊天也能理解项目；AI 不依赖完整聊天历史也能继续维护项目。

共同工作的中心是一张有固定节点格式的开发方向图。它表达当前有效的目标、实施路径、依赖、实际进展、验证结果和需要人的输入。AI 结合讨论与实际开发持续维护它。

产品包含网页、MCP 服务、共享 XML 存储和配套 Skill。完整模拟 XML 示例用于体验与验证。

## 阅读方式

### 项目总览

打开项目先呈现项目目标，以及各项需求的当前情况。重点是：关键进展、主要阻碍、下一步、需要人回应的事项。

需求状态从节点和完成条件汇总；AI 另外维护简短叙述，解释这些状态意味着什么。总览不保存另一套独立进度，不按节点完成数量推算交付百分比。

人的意见尚未被整合时，总览应直接显示“有新的输入待同步”。避免意见已经提交而正文仍显得完全最新。

### 需求子图

一项需求是一张图，复杂需求可以继续拆成子需求。默认展示当前层级，子需求作为可进入的入口，进入后保留上层路径。

图上直接可见：

- 实施步骤、必要前提和可并行分支。
- 分支汇合的集成节点、验证节点、最终验收与交付节点。
- 当前进行中、受阻、失败或待复核的位置。
- 需要人填写的节点，以及不属于本期交付的后续事项。

跨需求关系显示外部引用入口，打开后查看其原始内容，不在本图复制维护一份。

类型决定节点样式，进度使用明确文字。实线表示必要依赖；引用与后续关系使用独立的线型和文字，不能只依赖颜色区分。图例始终解释箭头含义。

普通字段更新保留节点位置、选中与展开状态；结构变化只调整必要区域。布局与展开状态属于阅读偏好，不写进正式业务内容。

### 节点详情

节点展开固定采用以下顺序：

1. 名称与当前状态。
2. 当前情况：已有结果和主要差距。
3. 本类内容：按照类型展示固定字段。
4. 下一步：做什么，以及需要 AI、人或外部条件中的哪一方参与。
5. 关联关系：从连线自动生成前提、后继与引用。
6. 依据：代码、实际执行结果、相关文档。
7. 附件。AI 上传的图片和 Markdown，可预览或下载。
8. 人的记录：原始意见、回答、决定与验收结论。

同类节点始终使用同一种展开格式。可选且无内容的区域隐藏；应有但尚未产生的结果显示“尚未执行”等真实说明，不要求 AI 编造填满模板。

正文支持文本、段落、列表、强调、内联代码和链接。呈现由模板控制，不接受自由 HTML、脚本或自定义样式。证据与长记录默认收起，当前结论先显示。

## 节点与范围

### 需求容器和需求分析节点

需求容器保存整项需求的目标、范围、摘要和最终完成条件，并包含工作节点及子需求。

需求分析节点是其中一项工作。分析结束说明问题、边界和验收依据已整理；它不自动表示开发获得授权，也不代表整个需求完成。

容器的目标和范围是面向读者的当前约定，分析节点保留形成这些约定的分析结果。AI 在约定变化时一并校准，不能保留互相矛盾的两个版本。

### 十三类节点

| 类型 | 表达什么 |
| --- | --- |
| 需求分析 | 问题、范围和验收依据 |
| 调研 | 待回答问题、已发现事实和未知项 |
| 只读依赖 | 本次引用但不修改的已有能力 |
| 假设 | 尚需证实的前提及其影响 |
| 决策 | 候选方案、选择及理由 |
| 设计 | 结构、接口约定和约束 |
| 实现 | 实现范围、产出和剩余工作 |
| 集成 | 汇合对象、连接方式与实际情况 |
| 验证 | 自动化测试或人工验证的过程及结果 |
| 评审 | 发现及处理结论 |
| 交付验收 | 对照需求检查是否接受交付 |
| 发布交付 | 实际交付操作、产物和交接说明 |
| 后续事项 | 本期暂缓的事项及重启条件 |

修复复用实现模板，以 `variant="fix"` 标记并关联问题来源。验证通过 `method` 区分自动和人工。完整字段及状态规则以[节点契约](node-contract.md)为准。

可独立推进、并行实施或单独检查的工作适合拆成节点。细小操作放在节点内部，不要求每次命令、每个函数或每个文件都对应一个节点。十三类是可选类型库，不要求每项需求配齐。

## 关系与真实状态

### 三种连线

| 关系 | 方向与含义 |
| --- | --- |
| `requires` | 前提 → 后继：按当前计划，后继需要此前提成立 |
| `references` | 依据 → 使用者：提供上下文，不阻塞推进 |
| `follow_up` | 当前工作 → 后续事项：表达后续演进，不阻塞本期交付 |

需求的 `parent` 表示归属，不代表执行顺序。并行性从必要依赖关系得出，不另存“可并行”字段。

必要依赖和完成条件的递归求值不能形成循环。返修更新原节点或新增修复节点，通过引用关联问题来源，不能用一条反向硬依赖把执行图连成环。

### 工作、结果、有效性分别记录

“测试执行结束”与“测试通过”是两件事；“过去通过”与“现在仍适用”也不同。

内部保存工作状态、结果和有效性。页面合成为一句话，例如“实现完成”“测试失败”“曾通过 · 待复核”。需要时再查看内部字段和依据。

节点本身满足、其必要前提满足是两个可单独解释的事实。依赖满足要求有效的成功结论，整个需求完成还要求指定完成节点及其必要前提均满足。未来事项不参与本期完成计算。

没有指定完成条件时，显示“完成条件未定义”。分析节点的完成、节点数量比例和 AI 的概览摘要都不能代替验收与交付状态。

### 方向图允许记录现实中的偏差

上游未满足时，仍可以记录已经写出的代码、已经执行的测试和失败结果。页面提示“上游未满足”等不一致，AI 再核对遗漏记录、修正关系或标记待复核。

服务只对能确定的格式和结构错误拒绝保存。业务事实是否正确由 AI 核对，工具不会因为字段填写完整就宣称功能正确，也不会因为图中的顺序而阻止记录现实。

## 人的输入

默认在需求分析、决策、人工验证、交付验收节点提供填写入口。人填写意见和明确结论，AI 负责维护正文及图结构。这是协作方式，不是账号权限系统。

输入作为独立记录保存原文、来源、记录者、入口和处理情况。来自网页的填写与 AI 从聊天中记录的决定分开标记；AI 的概括与人的原话分开。

普通建议不自动生效为已确认要求。明确决定和验收结论先原样保存并立即可见，涉及的正文与关系由 AI 整合。处理完毕后标记已同步；存在歧义时标记待澄清并说明下一步。

人的原始记录不能在节点整理中消失。输入存在错误时，通过追加更正记录保留修正过程；AI 可以调整其处理情况，不能把自己的推断改写为人的原始结论。

## 工具组成与职责

```text
AI ── MCP 入口 ──┐
                  ├── 共享读写、校验与保存 ── .hsdd/story.xml
人 ── 本地网页 ──┘
```

| 部分 | 职责 |
| --- | --- |
| Skill | 理解需求和代码、选择类型、拆分和维护节点、判断更新时机、写清楚事实与未知 |
| MCP | 提供结构化的局部读取和批量修改工具，返回真实保存结果 |
| 本地服务 | 校验节点和关系、处理版本冲突、原子保存、提供页面阅读数据 |
| 网页 | 固定布局和字段展示、逐层阅读、呈现阻碍与待回应事项、提交人的输入 |
| XML | 保存正式状态、来源、证据及必要历史 |

网页与 MCP 使用同一保存逻辑。XML 是正式内容源，页面缓存不保存另一份正式状态。MCP 工具只维护图，不执行代码、测试、部署或自动调度开发。

Skill 必须实际加载，或其规则被明确纳入项目规则后才能约束工作。工具安装不等于每轮会话自动维护。

## AI 维护规则

### 读取和更新时机

新会话先读概览与版本，再读取本轮有关的子图和人的未处理输入。优先解释当前目标、阻碍和下一步，按需扩展到代码与证据。

以下情况触发更新：需求或决定变化、实现取得实质进展、获得检查结果、发现新阻碍、修正既有事实，或调整图结构。

一轮中的关联变化合并提交；长任务在有意义的阶段成果出现时保存。普通问答、重复解释和没有形成实质变化的探索不制造版本或同步记录。

每次修改以字段和相关节点为单位，通过 MCP 提交结构化操作。AI 不重新生成页面，也不反复重写整个 XML。保存成功后才报告已同步；未保存的内容不能被当作下次会话可读的结果。

### 纠正、删除、合并、拆分和重连

纠正保留稳定 ID。合并与拆分生成新的 ID，旧节点退出当前图并保留替代关系。连线和重要记录如何迁移，必须在同一修改批次中明确。

工具不猜测拆分后的任务归属，也不直接把旧测试结论复制成新节点的有效结论。AI 明确判断哪些依据仍适用，无法确定的标记待复核。

第一版删除节点时，当前图移除该节点并统一归档，保留人的记录、验收依据与替代关系。整理图不能扩大开发授权或擅自改变已确认需求。

### 版本与证据

项目每次真实保存增加版本。节点的实质内容变化更新其修订号，纯措辞整理保持语义修订号。证据记录针对的节点修订号或代码版本。

明确引用的依据过期时，相关结论标记待复核；其他可能受影响的节点作为提示交给 AI 核对。不会把每次措辞修改都当成整图失效，也不承诺自动发现所有外部代码变化。

### 保存失败和并发

网页与 MCP 提交时携带读取版本和不透明快照标识 `readToken`。快照标识用于发现外部编辑未递增版本号的情况，不承担认证功能，也不写入 XML。版本或快照冲突要求重读后提交，不静默覆盖。多项操作通过校验后一起保存，任何一项失败都不产生部分更新。

发现文件被外部改动时先重读和校验；不能拿旧内存副本覆盖磁盘新内容。保存失败明确返回未保存，页面保留待提交输入并显示失败。

读取、更新和错误结果的具体约定见[MCP 契约](mcp-contract.md)。

## 验收场景

这些场景用于验证运行行为。测试入口见 [README](../README.md)。

| 场景 | 预期结果 |
| --- | --- |
| 人首次打开项目 | 不读聊天即可找到目标、当前进展、阻碍、下一步和需自己回应的事项 |
| AI 在新会话续接 | 读取概览与相关子图即可恢复任务，需要时再读取证据 |
| AI 更新与人填写 | 两个入口修改同一份数据，页面和下一会话均可读到 |
| 合并、拆分、删除 | 无悬空关系，人的有效记录和依据仍可追溯 |
| 测试失败或证据过期 | 显示真实失败或待复核，不与已交付混淆 |
| 上游未满足但已有实际工作 | 事实可以保存，不一致明确可见，完成判断不被误导 |
| 版本冲突、非法操作、保存失败 | 明确报错，不部分保存，不静默丢失输入 |
| 同类节点与普通更新 | 展开格式稳定，布局和阅读位置不无故改变 |

当前默认本地、单用户、多需求，不建设通用文档平台、账号体系或开发调度系统。
